Full technical documentation of this repository: what every module and function does,
the logic behind each step, the data it operates on, and how the pieces fit together
into one end-to-end machine-learning pipeline.

## 1. Project Goal

The project trains and evaluates a **binary classifier** that decides whether a piece
of text was **written by a human (`0`)** or **generated by AI (`1`)**.

The core idea: rather than hand-engineering linguistic features, each text is converted
into a dense numeric vector (an *embedding*) by the **BGE-M3** sentence-transformer
model, and a classic scikit-learn classifier is trained on those vectors. Several
candidate models compete; the winner is hyperparameter-tuned, saved to disk, and scored
on a held-out test set.

## 3. The Dataset — `data/original_data.csv`

2,000 rows × 9 columns. Class balance: **1334 human / 666 AI**.

| Column | Meaning |
|--------|---------|
| `text_id` | Unique row identifier (e.g. `TXT_0001`). |
| `label` | Ground-truth class: `human` or `ai`. **This is the target.** |
| `source_model` | Who/what produced the text (`human`, `GPT-4o`, etc.). |
| `domain` | Topic domain: `social`, `news`, `academic`. |
| `text_content` | **The raw text** that gets vectorized. |
| `topic_hint` | Short phrase describing the subject. |
| `word_count` | Pre-computed number of words. |
| `avg_sentence_length` | Pre-computed average sentence length. |
| `generation_method` | How the text was produced (e.g. `template+human_variation`). |

Only **`text_content`** (features) and **`label`** (target) are consumed by the
training pipeline. The other columns are used in the exploratory notebook.

## 5. `src/main.py` — Orchestrator & Entry Point

This is the file you run (`python src/main.py`). It wires the three stages together and
owns all logging configuration.

### Module-level setup (lines 8–20)

- Configures the root logger to `INFO` level with a timestamped format streaming to the
  console.
- Silences noisy third-party libraries (`httpx`, `filelock`, `huggingface_hub`,
  `transformers`, `urllib3`) by raising their level to `WARNING`. Because every other
  module just calls `logging.getLogger(__name__)`, they all inherit this single config.

### `run_pipeline()`

**Purpose:** Orchestrate the entire ML lifecycle from raw CSV to final metrics.

**Logic, step by step:**

1. **Path resolution** — `Path(__file__).resolve().parent.parent` walks up from
   `src/main.py` to the repo root, then builds `data/original_data.csv`. Using
   `__file__` makes the script runnable from any working directory.
2. **Data-ingestion guard** — checks `data_path.exists()`; if missing, logs an error and
   raises `FileNotFoundError` immediately (fail fast instead of a cryptic pandas error).
3. **Load** — `pd.read_csv(data_path)` into `df`; logs the shape.
4. **Feature extraction** — calls `process_data_for_pipeline(df, 'text_content', 'label')`
   to get the numeric `vector_df`.
5. **Split** — `prepare_data(vector_df)` → `X_train, X_test, y_train, y_test`.
6. **Train & tune** — `find_and_train_best_model(X_train, y_train)` selects the best
   model, tunes it, and serializes it to disk.
7. **Evaluate** — `evaluate_saved_model(X_test, y_test)` loads the saved model and prints
   metrics on the untouched holdout split.
8. **Error handling** — steps 4–7 are wrapped in `try/except`; any exception is logged
   with a full traceback via `logger.exception(...)` and re-raised so the process exits
   non-zero.

### `if __name__ == "__main__"` block

Runs `run_pipeline()` and catches `KeyboardInterrupt` separately, logging a clean
"manually interrupted" warning instead of dumping a stack trace when you Ctrl-C.

## 6. `src/nlp.py` — Feature Extraction (Text → Vectors)

This is the bridge between **unstructured text** and **structured numeric features**.

### `process_data_for_pipeline(df, text_col, label_col)`

**Purpose:** Map text labels to integers, embed every text with BGE-M3, and return a
fully numeric DataFrame of features + label.

**Logic, step by step:**

1. **Label mapping** —
   ```python
   label_mapping = {"human": 0, "ai": 1}
   processed_labels = df[label_col].map(label_mapping).astype(int).values
   ```
   Turns the problem into binary classification. `.values` strips the pandas index to a
   plain NumPy array.
   > ⚠️ **Edge case:** any label that is not exactly `"human"` or `"ai"` (typos, `"Human"`,
   > blanks) becomes `NaN`, and the following `.astype(int)` then raises. The step
   > silently assumes a clean dataset using exactly those two labels.

2. **Device selection** — `device = "cuda" if torch.cuda.is_available() else "cpu"`.
   Embedding is the slowest stage; GPU is dramatically faster but CPU works too.

3. **Load embedding model** —
   ```python
   model = SentenceTransformer('BAAI/bge-m3', device=device)
   model.max_seq_length = 8192
   ```
   Loads **BGE-M3** from the Hugging Face Hub (first run downloads several GB, then
   caches). It produces a **1024-dimensional** vector per text. The max sequence length
   is raised to **8192 tokens** so long texts are truncated less aggressively.

4. **Encode** —
   ```python
   emb = model.encode(df[text_col].tolist(),
                      batch_size=32,
                      show_progress_bar=True,
                      normalize_embeddings=True)
   ```
   Returns a NumPy array of shape `(N, 1024)`.
   - `batch_size=32` — throughput/memory trade-off.
   - `show_progress_bar=True` — console progress bar.
   - `normalize_embeddings=True` — L2-normalizes each vector to unit length, so dot
     products equal cosine similarity; this generally helps downstream linear and
     distance-based models.

5. **Build output DataFrame** —
   ```python
   feature_names = [f"feat_{i}" for i in range(emb.shape[1])]   # feat_0 … feat_1023
   pipeline_df = pd.DataFrame(emb, columns=feature_names)
   pipeline_df['label'] = processed_labels
   return pipeline_df
   ```

**Output shape:** `(N, 1025)` → 1024 `feat_*` columns + 1 `label` column. This is
exactly the format `prepare_data()` expects.

> **Note:** the model is reloaded on every call. Fine here (called once per run), but it
> would be worth caching/injecting if called repeatedly.

## 7. `src/train.py` — Split, Model Selection, Tuning, Save

The heaviest module. It contains the "compete → pick winner → tune winner → persist"
logic, split across five functions.

### `prepare_data(df, test_size=0.2, random_state=42)`

**Purpose:** Separate features from target and produce a stratified train/test split.

**Logic:**
- `X = df.drop(columns=['label'])` — all `feat_*` columns.
- `y = df['label']` — the target.
- `train_test_split(..., test_size=0.2, random_state=42, stratify=y)`:
  - **80/20** split.
  - `random_state=42` — reproducible split.
  - `stratify=y` — preserves the human/AI class ratio in both splits (important given the
    ~2:1 imbalance).
- Returns `X_train, X_test, y_train, y_test`.

### `get_model_pool(random_state=42)`

**Purpose:** Define the candidate models that will compete.

Returns a dict of 4 estimators (the docstring says "5" — a minor inaccuracy):

| Key | Estimator |
|-----|-----------|
| `Logistic_Regression` | `StandardScaler` → `LogisticRegression(max_iter=1000)` |
| `Random_Forest` | `RandomForestClassifier` |
| `Gradient_Boosting` | `GradientBoostingClassifier` |
| `Support_Vector_Machine` | `StandardScaler` → `SVC` |

Linear/margin models (LogReg, SVC) are wrapped in `make_pipeline(StandardScaler(), …)`
because they are scale-sensitive; the tree ensembles are not, so they stand alone. Every
estimator gets the same `random_state` for reproducibility.

### `get_hyperparameter_grids()`

**Purpose:** Define the GridSearch search space per model.

Returns a dict mapping each model name to its parameter grid. Key detail: parameters of
an estimator **inside a pipeline** must be prefixed with `stepname__`, e.g.
`logisticregression__C` or `svc__gamma`, whereas the standalone tree models use bare
names like `n_estimators`. Grids:

- **Logistic_Regression:** `C ∈ {0.1, 1.0, 10.0}`
- **Random_Forest:** `n_estimators ∈ {100,200}`, `max_depth ∈ {10,20,None}`, `min_samples_split ∈ {2,5}`
- **Gradient_Boosting:** `n_estimators ∈ {100,150}`, `learning_rate ∈ {0.01,0.1,0.2}`, `max_depth ∈ {3,5}`
- **Support_Vector_Machine:** `C ∈ {0.1,1.0,10.0}`, `gamma ∈ {scale, auto}`

### `evaluate_model_pool(X_train, y_train, cv_folds=5, scoring='f1', random_state=42)`

**Purpose — Step 1:** Run baseline cross-validation across all models to pick the winning
*architecture* (before any tuning).

**Logic:**
- Builds the pool via `get_model_pool`.
- For each model, runs `cross_val_score(..., cv=5, scoring='f1', n_jobs=-1)` and stores
  the **mean F1** across folds.
- `scoring='f1'` (F1 of the positive/AI class) is chosen over accuracy because the
  classes are imbalanced. `n_jobs=-1` uses all CPU cores.
- Returns `(cv_results, models)` — a name→mean-score dict and the instantiated models.

### `train_and_save_best_model(best_model_name, best_model_blueprint, X_train, y_train, cv_folds=3, scoring='f1', model_dir=None)`

**Purpose — Step 2:** Take the winning model, tune it with `GridSearchCV`, and persist
the best version.

**Logic:**
1. Look up the winner's grid via `get_hyperparameter_grids()`.
2. **If a grid exists:** run `GridSearchCV(estimator, param_grid, cv=3, scoring='f1', n_jobs=-1, verbose=1)`,
   `.fit()` it, and take `grid_search.best_estimator_` (the model refit on all training
   data with the best params). Logs `best_params_` and `best_score_`.
3. **If no grid:** fall back to fitting the blueprint with default params.
4. **Persist:** resolve `model_dir` (defaults to `<repo_root>/models`), `os.makedirs(..., exist_ok=True)`,
   and `joblib.dump(final_model, 'best_model.joblib', compress=3)`.
5. Return the fitted `final_model`.

### `find_and_train_best_model(X_train, y_train, cv_folds=5, scoring='f1', random_state=42)`

**Purpose:** Orchestrator tying Step 1 and Step 2 together.

**Logic:**
1. `evaluate_model_pool(...)` → CV scores for all models.
2. `best_model_name = max(cv_results, key=cv_results.get)` — pick the highest mean F1.
3. Pull that model's blueprint and pass it to `train_and_save_best_model(...)` (note: the
   tuning phase uses `cv_folds=3`, a deliberately cheaper CV than the 5-fold selection).
4. Return the final tuned, saved model.

> **Current winner (as serialized in `models/best_model.joblib`):**
> a `StandardScaler → LogisticRegression(C=0.1, max_iter=1000)` pipeline.

## 8. `src/evaluate.py` — Final Scoring on the Holdout

### `evaluate_saved_model(X_test, y_test, model_path=None)`

**Purpose — Step 3:** Load the serialized model from disk and report comprehensive
metrics on the untouched test split.

**Logic:**
1. **Resolve path** — default `<repo_root>/models/best_model.joblib`; a relative
   `model_path` argument is resolved against the repo root, an absolute one is used as-is.
2. **Existence guard** — raise `FileNotFoundError` if the model file is missing.
3. **Load** — `joblib.load(model_path)`.
4. **Predict** — `model.predict(X_test)`.
5. **Metrics:**
   - `f1_score(y_test, predictions, pos_label=1)` — F1 of the AI class.
   - `confusion_matrix(...)`.
   - `classification_report(..., target_names=['Human (0)', 'AI (1)'])` — per-class
     precision/recall/F1.
6. **Confusion-matrix breakdown** — prints each quadrant in plain language:
   - `matrix[0][0]` → True humans flagged human (**TN**)
   - `matrix[0][1]` → True humans flagged AI (**FP**)
   - `matrix[1][0]` → True AI flagged human (**FN**)
   - `matrix[1][1]` → True AI caught (**TP**)
7. Return `final_f1`.

> Note: this module prints with `print(...)` rather than the logger used elsewhere, so its
> output always appears regardless of log configuration.

## 9. `notebooks/Clean Data and preprocessing.ipynb` — Exploratory Analysis

Not part of the training pipeline; a separate **EDA / stylometry** study used to justify
the modeling approach. Highlights:

- **Feature engineering helpers:**
  - `compute_word_diversity(text)` — Type-Token Ratio (unique words ÷ total words),
    measuring vocabulary richness.
  - `compute_punctuation_density(...)` — punctuation marks relative to text length.
- **Visualizations** (saved as PNGs in `notebooks/`): label distribution, source-model
  distribution, punctuation density by source model, word diversity by source model, and
  advanced stylometric plots.
- **Key findings** documented in the notebook's markdown:
  - AI text shows **higher punctuation density** than human text.
  - AI **lexical diversity (TTR) is rigidly narrow** (~0.93–0.95) — "robotic uniformity"
    — whereas humans span a much broader range.
  - The dataset is **balanced across domains** (academic, news, social).

These observations support the project thesis: AI text is statistically more uniform,
which embedding-based models can exploit.

## 11. Design Notes, Caveats & Improvement Ideas

- **Empty `requirements.txt`** — dependencies are not pinned; add `sentence-transformers`,
  `torch`, `scikit-learn`, `pandas`, `numpy`, `joblib`.
- **Data is git-ignored** (`.gitignore` excludes `*.csv`), so the pipeline cannot run on a
  fresh clone without supplying the dataset.
- **`get_model_pool` docstring says "5 models" but defines 4** — a harmless mismatch.
- **Label mapping is brittle** — any unexpected label crashes `.astype(int)`; add
  validation.
- **BGE-M3 reloaded each call** — fine for a single run; cache/inject if reused.
- **Mixed output channels** — `nlp.py`/`train.py`/`main.py` use `logging`; `evaluate.py`
  uses `print`. Unifying on the logger would be cleaner.
- **No held-out leakage** — note the embeddings are computed on the *whole* dataset before
  the train/test split; since BGE-M3 is a fixed pre-trained encoder (not fit on this
  data), there is no label leakage, but the `StandardScaler` inside the saved pipeline is
  correctly fit only on the training folds during CV/GridSearch.
